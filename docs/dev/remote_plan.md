# The remote layer, the OpenNeuroDerivatives source and `review openneuro:dsXXXXXX`

The plan of the second stage of milestone 5, as laid down by its first work package, R0 ("shared names"), on 2026-11-15 at 11731a3. It was written from a planning pass that read the code and ran nothing, and corrected where R0 found the code or the decisions to differ (section 9). The decisions it rests on are D47 in `decisions.md`, each a default for Tomas to change. This file is not imported by `CLAUDE.md`; `architecture.md` (Sources) points here.

What R0 built is complete and tested: the shared names, constants, records and signatures; the read-only transport with the limit of the process; the parsing of `openneuro:dsXXXXXX`; the names of the cache; the stored form of a remote dataset in a local run and how `Run` makes, opens and rebuilds such a run; the fake bucket of the tests. What the other packages write is a stub that raises `NotImplementedError("work package RA: remote/s3.py")` and the like. Nothing of this stage has touched the network: every test runs against the fake. No command takes `openneuro:` yet.

## 3. Identity, salt and pseudonym of a remote review (decision D47, item 1)

`review openneuro:dsXXXXXX` makes a local run: `mode: local`, `identity.kind: local-salt`, the `app` defaults of a local run.

The dataset record (RE): `source = "openneuro-derivatives"`, `identity = accession = dsXXXXXX`, `root = s3://openneuro-derivatives/fmriprep/dsXXXXXX-fmriprep/` (`dataset_root`), `fs_root` `sourcedata/freesurfer` or `freesurfer`, layout and pipeline as the local rules give them, `pipeline_version` from `dataset_description.json`, `template_location` when `fs_root/fsaverage/` lists the eight files.

The pseudonym is `HMAC(salt, "openneuro-derivatives:dsXXXXXX")` (`privacy.dataset_pseudonym` with the run's salt), and `subject_uid` is keyed by the salt as for any local run, so two users' runs of one public subject are not linkable. The same files downloaded and reviewed as a folder get other identifiers (source `local`, identity the path); that is intended.

Where the accession is, under decision 1:

- `catalog.sqlite`: `datasets.accession`, `identity` and `root`. Nowhere else in the run directory.
- `config.yaml`: `SourceConfig(kind="openneuro-derivatives", bucket="openneuro-derivatives", prefix="fmriprep/", dataset="D-xxxxxxxx", subjects=(globs...))`. `SourceConfig` refuses an accession in any remote prefix, also in a census run, and subject globs on a remote source that is not stored by its pseudonym. `RunConfig` takes a remote source in a local run only as the one source of the run, of kind `openneuro-derivatives`, with a pseudonym; a census run takes remote sources by bucket and prefix only.
- The terminal lines of the user's own command (`review`, `status`): their own argument on their own terminal (D20's rule for a command's errors and the operator's `status`). The exception texts that R0 raises name the stored dataset by pseudonym only, since a `ConfigError` text can reach a log.
- The name of the default run directory, `./dsXXXXXX-surfcensus-run` (decision D47, item 2). In no file content.
- Never in the app, `export/`, `logs/`, `media/`, `render.json` (`inputs` names files, not keys), the names under `cache/` (keyed with the run secret, the basename of the key only) or a recorded failure detail (`scrub_with` turns the accession into the pseudonym; `remote.source_error` reduces a URL to its last component).

How it works end to end (all of it built by R0 but the listing, which is RE's):

1. A new run. `RZ` builds `OpenNeuroDerivatives(client=S3Client(...), accession="dsXXXXXX", subjects=globs)` and calls `Run(run_dir, source, transport=...)`. The source holds no cache and no pseudonym yet: the cache is keyed with the run secret, which exists only once the catalog is made, and the pseudonym is keyed with the salt, which `new_local_config(None)` draws. `Run._create` draws the configuration without a source, computes the stored form with `remote_dataset_config(base, accession, subjects=globs, bucket=...)`, writes `config.yaml` (exclusively, as for any run) and the catalog, binds the source (`source.bind(cache=Cache(run_dir/"cache", secret=run_secret, ...), pseudonym=...)`) and writes the dataset row from `source.datasets()`, the one place the accession is kept. That listing is a few requests and is the first the run makes. A census run is made the same way from `OpenNeuroDerivatives(client=..., prefix="fmriprep/")` and the key: bound to the cache, stored by bucket and prefix. A source of one dataset given to a census run is refused.
2. The same dataset again. `review openneuro:dsXXXXXX` finds the run without the catalog: `remote_index(config, accession)` recomputes the pseudonym from the typed accession and the salt in `config.yaml` and compares it with the stored `dataset`. Given to `Run(run_dir, source)`, `_adopt_remote` matches it the same way, takes the source's globs (as a local source's), binds it, and writes the dataset row when the catalog has none, which repairs a run whose creation stopped between `config.yaml` and the row. No request is made when the row is there.
3. Rebuilt from the run alone. `Run(run_dir)` and a phase that needs the source: `Run._source` reads the accession from the catalog by pseudonym and calls `from_config(stored, config, run_dir, identity=accession, transport=..., secret=run_secret)`, which checks that the accession gives the stored pseudonym with the salt (`ConfigError("key", ...)` otherwise) and builds the client and the cache without a request. A catalog without the row stops with `invalid: the catalog has no dataset D-... of config.yaml: run the command again with the dataset named (openneuro:dsXXXXXX), which records it`.
4. Another root. Another accession, or a local path, given to a run on a remote dataset is `other root`: `this run directory belongs to D-xxxxxxxx, a dataset of the openneuro-derivatives bucket, not to the dataset given: give it a run directory of its own with --run-dir DIR`. A remote dataset given to a run of a local root is `other root` with the root named. The accession of neither is in the message.
5. `--relocate` with a remote dataset is `invalid: a remote dataset does not move; --relocate is for local data`.

## 4. The command (RZ)

`surfcensus review openneuro:dsXXXXXX [--subjects GLOB]... [the other options of review]`

- Parsing: `remote.parse_remote_path(text)`. `openneuro:` followed by `ds` and six ASCII digits is the dataset, also when a folder of that name exists (decision D47, item 8); any other text that starts with `openneuro:` is `invalid`; every other text, `./openneuro:x` included, is a path.
- Run directory: `./dsXXXXXX-surfcensus-run` in the current directory (`RemoteRef.run_dir_name`; decision D47, item 2), or `--run-dir`. A run there of another source gives `other root` with exit code 2.
- Refused with one line and exit code 2: `--relocate`, `--raw`, `--epi`, `--epi-runs` (decision D47, item 4: no EPI for a remote dataset), `--field-strength` (item 7). The functional inventory and `epi_run_stems` skip non-local sources already, so the app gets no `/epi` link.
- Order, as D33: list; inventory (Tier A of every subject; stats into the retained cache, build stamp and logs into memory); metrics (the template once, then Tier B in batches of `cache.batch_subjects`; with `--blind` too, decision D47, item 5); the first render (Tier C and both `sphere.reg`, 34 to 40 MB); the app; the rest rendered behind it in batches of `--jobs`.
- The estimate and the guard (item 3). After the listing (about N + 5 requests, no file content) and before any file is read, `review` prints what it will fetch, from the listed sizes: before the first rating screen (Tier A and B of every subject, the template unless one is pinned or `$FREESURFER_HOME` has one, the first render) and in all. For a new run, or a changed subject set, without `--subjects`, it stops with exit code 2 when the first figure exceeds 2 GB (about 135 subjects) and asks for `--subjects`; `--subjects '*'` counts as asking for all. No `--limit`.
- Lines on stderr (new ones marked; the figures below are arithmetic from the sizes in `tests/conftest.py` and the tiers in `CLAUDE.md`, sub-02 assumed like sub-01, not measured):

  ```
  Run directory: ./ds000102-surfcensus-run (new)
  Listing openneuro:ds000102 in s3://openneuro-derivatives, anonymously and read-only ...   [new]
  Found 2 subjects in openneuro:ds000102 (fMRIPrep layout, FreeSurfer 6.0.1, of the subjects matching sub-0[12]).
  To fetch: 108 MB before the first rating screen (...), 148 MB in all; source files are deleted after use, at most 0.5 GB on disk at once.   [new]
  ...
  Rating app: http://127.0.0.1:8765/ (NN s after the start; 108 MB fetched in 53 requests)   [bytes and requests new]
  ... and at the end: Fetched 148 MB in 61 requests in all; 0 MB of source files left in the cache.
  ```

  The counts come from `remote.stats()`.
- A second call lists again and fetches nothing that did not change; a changed ETag inventories that subject again (D21).

## 5. Disk, load, signals, resume

- Concurrency. At most `MAX_CONCURRENCY` (8) requests open in the process: the transport takes a slot for every request and gives it back when the response is closed or read to the end (R0), so no client or thread can open more. Under it each client has a semaphore of `RemoteConfig.max_concurrency` (validated at most 8; the tests use 4), which RA takes around each request. In `review` only one thread downloads at a time (the main thread before the app, the renderer thread after it), inferred from `review.py` and not run.
- Retries (RA). Exponential backoff with full jitter (`RETRY_BASE_S` 0.5 s doubled per attempt, `RETRY_CAP_S` 30 s), `Retry-After` honoured up to the cap, up to `max_retries`, slept through the client's `sleep`. Retried: 500, 502, 503, 504 (`SlowDown` among them), connection errors, read timeouts, a body shorter than its `Content-Length`, a body whose MD5 is not its ETag. Not retried: 400, 403, 404, 412, 416.
- Machine against subject (D29, decision D47, item 10). Retries that run out are `SourceError("unreachable")`; a phase whose batch holds one stops at that batch, records nothing of it and exits with 2 (RC). A 404 on a listed key and a 412 are `changed`, a 403 `unreadable`, each a failed row of its subject as today. A listing that cannot be had at `datasets()` is raised as it is and gives exit code 2 through `cli._stops_with_exit_2`.
- The cache (R0 and RB), under `run_dir/cache/`: `leases/<host>-<pid>/<h>/<basename>` and `retained/<h[:2]>/<h>/<basename>`, `h = privacy.cache_name(run_secret, bucket, key, etag)`. Every download goes to a temporary name in the process's lease area, is checked for size and MD5, and is renamed, into `retained/` when retained; `retained/` never holds a partial file.
- The disk bound. The bytes of one batch are `batch_subjects` times the largest leased subject. Before `metrics` or `render` on a remote source, `Run` (RZ) computes it from the private catalog's sizes and, when it exceeds `cache.max_bytes`, lowers `batch_subjects` for that call (one log line). `Cache.lease` raises `CacheBudgetError` (a `ConfigError`, reason `invalid`) when the process's leases plus the request exceed the budget, and does not wait (item 9): a lease in the one thread that leases could never be freed by another. `Run` also refuses, with exit code 2, a call where the free disk is less than one batch plus `DISK_MARGIN_BYTES` (500 MB). For a review: metrics peak about 32 x 14 MB = 0.45 GB, renders `jobs` x 40 MB at most 0.32 GB, plus 40 MB of template and about 22 kB per subject retained. The census default is about 32 x 43 MB = 1.4 GB.
- Pruning (RB and RZ). Each process holds `flock` on `leases/<host>-<pid>/.lock` (`msvcrt` on Windows). `Cache.prune()` runs when a remote source is built and removes the areas of this host whose lock it can take; areas of other hosts are reported. `Run.prune_cache()` (RZ) removes retained objects that the catalog's present `files` rows no longer name (`Cache.forget`), and the retained `fsaverage/` once `templates/<id>/` reads. `sphere.reg` is not retained between metrics and render (item 6).
- Ctrl-C and SIGTERM reach the main thread as `KeyboardInterrupt`. A lease waits on its downloads in a loop with a short timeout and sets a cancel event that `S3Client.download` checks per `CHUNK_BYTES` (1 MiB), so a stop takes about one chunk per open download; on exit it removes what it downloaded, partial files included. Exit codes 130 and 143 as today.
- SIGKILL leaves the lease area with partial files; the next start prunes it. Workers only read leased paths and end with their parent (D45). That a spawned worker does not inherit the lock's descriptor is inferred, not checked.
- Resume: the skip rules are unchanged. Retained files are reused by name; a pinned template is read from `templates/` once `_find_template` is lazy.
- `scripts/fetch_example.py` stays as it is in this stage, as the way to get functional data for a local review. Its listing loop and its write-then-rename carry over into `remote/s3.py`; its one client per file, its missing ETag, If-Match, Range, MD5, retry and guard do not.

## 7. Testing without the network

`tests/fakes3.py` (R0, complete) serves directories as buckets, links followed. One handler is reachable as an `httpx.MockTransport` (`FakeS3.transport()`) and as a `ThreadingHTTPServer` on 127.0.0.1 (`FakeS3.serve()`, which yields the endpoint to set as `SURFCENSUS_S3_ENDPOINT` for a subprocess). It answers ListObjectsV2 (`list-type=2`, `prefix`, `delimiter`, `CommonPrefixes`, `continuation-token`, `start-after`, `max-keys`, and a page size of its own, which tests set to 2 or 7), GET and HEAD with `Range` (206 and `Content-Range`, a suffix range, 416), `If-Match` (412), a quoted MD5 as ETag, `Last-Modified`, and with `version_ids` an `x-amz-version-id`; virtual-hosted and path-style requests. Any other method is 405; a request with `Authorization` or a signed query is 403 and kept in `FakeS3.signed`. Faults by key pattern (`fault(pattern, kind, times=..., methods=..., retry_after=...)`): `500`, `503`, `slowdown` (503 with the `SlowDown` body and an optional `Retry-After`), `truncate` (the full `Content-Length`, half the body, then a dropped connection), `reset`. `mutate_after_list` serves other content for a key once a listing has named it, without touching the file. `latency_s` per request, a request log (`log`, `methods`) and a high-water mark of concurrent requests (`high_water`). `bucket_of(cohort, accession="ds999999", root=...)` lays a synthetic cohort (or a subjects directory) out as `fmriprep/ds999999-fmriprep/{dataset_description.json, sourcedata/freesurfer -> cohort}`, with the `fsaverage` that the cohort links next to its subjects; `key_of` gives a subject's key. The fake writes no file.

### What RA, RB, RC and RE need to know beyond the stubs

- RA: use `self.http` for every request, and nothing else. `httpx.Client` with `trust_env=True` mounts the proxies of the environment beside an explicit transport, which would pass around the guard; that is why the constructor sets `trust_env=False` and `default_transport` takes the proxy itself. Take `self.slots` around a request and the reading of its body. Close every streamed response: the process slot is given back on close or on the end of the body. `httpx` turns credentials in a URL into an `Authorization` header, which the guard refuses. Errors through `remote.source_error` (a URL in an exception text becomes its last component). A 416 is `invalid`. `S3Head.size` of a 206 comes from `Content-Range`.
- RB: `path_for` and `name` are fixed; the lease area is `self.area`. A download goes to a temporary name inside `self.area`, not inside `retained/`, and is renamed (one file system). `CacheBudgetError` takes only the detail. A worker process gets paths, not the `Cache`: the pid of the area is that of the process that made the cache.
- RC: `batches.run_batches` catches `Exception` around a lease and hands it to `commit` as the unit's outcome; that is where an `unreachable` or a `ConfigError` must stop the phase, before the commit writes anything. `KeyboardInterrupt` is no `Exception` and passes as it does today.
- RE: `kind`, `accession`, `globs`, `pseudonym`, `prefix`, `client`, `cache` and `bucket` are set by the constructor; `self.cache` is None until the run binds it, and a lease before that raises `ConfigError("invalid", ...)`. Roles through `patterns.roles_from_keys` and `key_variant`, candidates through `is_subject_candidate_keys` (a bucket has no empty folders, so an `mri/` without keys is no candidate), the version through `parse_pipeline_version`. `datasets()` of the one-dataset source must yield a record whose `identity` is the accession: `Run._remote_row` refuses another. Memoize the listing for the life of the source.

## 9. Where R0 departed from the planning pass, and why

- Decision 1 is the plan's option B (accession in the catalog only), not its option A (accession in `config.yaml` as the dataset prefix), by the hard rule of `CLAUDE.md`. So `SourceConfig` stores the pseudonym and `prefix: fmriprep/`, and `Run` keeps the accession in the dataset row (section 3).
- `new_local_config(source: SourceConfig)` cannot work: the pseudonym in the stored source is keyed with the salt that the function draws. It is `new_local_config(None)`, which gives a configuration without a source, and `remote_dataset_config(config, accession, ...)`, which computes the stored form from that configuration's salt.
- The cache is keyed with the run secret, which exists only once the catalog is made, so a source made before its run cannot hold a cache. `RemoteSource.bind(cache=..., pseudonym=...)` is how the run gives it one; `from_config` builds a bound source. `config()` of a one-dataset source raises before it is bound, since it has no stored form without its pseudonym.
- The process-wide limit and the counters sit in the transport, not only in the client: a slot is held from the request to the close or the end of the body, so no client and no thread can exceed 8. A body that a transport has in memory already (`httpx.MockTransport`) is counted and its slot given back at once: `httpx` does not close a response it has read, and the slot would leak.
- `default_transport` takes the proxy of the environment itself and the client does not trust the environment, for the reason under RA above. That `NO_PROXY` matching is a suffix test on the bucket host is an approximation.
- `remote/__init__.py` imports the standard library only and takes the transport from a module of its own (`remote/transport.py`) on first use, so that parsing `openneuro:` loads no `httpx`.
- `parse_pipeline_version` does not move out of `local.py`: the rule is `inventory.provenance.parse_dataset_description`, which `patterns.parse_pipeline_version` wraps (imported where it is called, since `provenance` imports `patterns`), and `local.py` now reads through it.
- An accession is refused in any remote prefix, also in a census run, so the single-dataset prefix of the plan's section 2 (`datasets()` of a one-dataset prefix) is gone: the census source lists `fmriprep/` and narrows by `only`, the review source by its `accession`.
- `STATUS_REASONS` has 416 as `invalid`; `Cache` gains `retained` and `forget`, which RE and RZ need; `CacheBudgetError` is a `ConfigError`, so it stops a phase as the faults of the machine do.
- Creating a run on a remote dataset lists the dataset (to write the row with the accession). A run whose creation stopped before the row was written opens, and is repaired by the next call that names the dataset.
- `privacy.scrub` gains `mask_subjects`, so that pseudonyms can be given in a local run without masking its labels.

Departures from the plan, with their reasons:

1. Order of the lines: Listing, Run directory, To fetch, Found. The guard must refuse before a run exists, and the estimate of a new run must be said before any file is read. For a continued run the line comes after the inventory (below).
2. The estimate of a continued run is not computed from the listing. It is what `metrics` and `render` would lease now by their own plans (`Run.remote_pending`: the pending units of the `fsaverage` stage and of the render, with the listed sizes from the catalog), said after the inventory. Reason: an estimate from what the run "holds" said that nothing would be fetched while every render was made again (the video turned on, media gone); the plans know. It is exact when the pinned template reads; without one it is an upper bound and says "at most".
3. `--no-epi` is refused as well as `--epi`.
4. A second call makes one GET besides the listings, `dataset_description.json`, which `datasets()` reads the fMRIPrep version from.
5. Version ids (`Catalog.set_file_versions`) and the `dataset_files` row are not built: a lease returns paths only and the source keeps the description private, so both need a change of signatures. The bucket does send `x-amz-version-id`. Traceability rests on ETag and SHA-256.
6. `inventory --source openneuro:...` is not built; `inventory`, `render-subject` and `epi-session` say that they read folders.
7. `Run.close` gives up the process's lease area (`Cache.release`), so a command that ended leaves nothing under `cache/leases/`; the plan left the lock file to the next prune.
8. `Run.prune_cache` runs at the end of every `Run.metrics` and removes nothing before the pinned template reads from `templates/<id>/`.
9. The disk bound (section 5) lowers the batch to what the free disk holds beside a margin (`run.disk_margin`: 500 MB, a quarter of a small disk) and refuses only a disk that does not hold one subject's files. The plan's fixed margin of 500 MB refused a review that needed 2 MB on a disk with 373 MB free, after the template was fetched and with advice that could not help. The template's room and a subject over `cache.max_bytes` are checked before anything is fetched for them.
10. A read that receives no byte for 30 s (`remote.s3.READ_STALL_S`) is given up, whatever `remote.timeout_s` says for the rest of a request. Nothing can interrupt a blocked read, so this is the longest a stop waits for a request that stalls.
11. A stop reaches every request: `S3Client.stop()` is set by `OpenNeuroDerivatives._parallel` when its thread is interrupted (listings, Tier A, the template), so that no request is started or retried and queued items are dropped. The plan had a cancel in leases only.
12. Statuses: 429 is retried; a status that is neither in `STATUS_REASONS` nor retried (407, 401, a redirect, 400) and an answer without an ETag are `unreachable` at once, since they say something about the way to the bucket; a body that never has the MD5 of its ETag is `changed` once the retries ran out, a row of its subject.
13. The renderer behind the app tries an unreachable bucket again every 30 s (`review.REMOTE_RETRY_S`) while the app runs, instead of ending.
14. `httpx`'s request log lines for the bucket hosts are filtered out (`remote.s3._NoRequestUrls`): they carry the accession, the key and the subject label at INFO.
